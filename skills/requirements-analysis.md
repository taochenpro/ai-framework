# Skill: Requirements Analysis

## Purpose

Convert unclear requests into implementation-ready requirements.

## Use When

- A new idea, feature, or bug needs scoping.
- Acceptance criteria are missing or vague.
- Product behavior must be separated from implementation details.

## Steps

1. Identify users, goals, constraints, and non-goals.
2. Write testable acceptance criteria.
3. Capture edge cases, permissions, data needs, and failure states.
4. Mark open questions instead of guessing.
5. Hand off ready work to the Project Coordinator Agent.

## Output Standard

- Requirements are clear enough for an independent agent to implement.
- Every task has acceptance criteria.
- Out-of-scope items are explicit.
